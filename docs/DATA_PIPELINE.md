## 选择与缺失上下文规则

首版只接受已确认私聊、普通文本类型 1、技术可读、有明确收发方向且本地复核通过的消息。未复核、压缩、媒体、身份未知、结构化文本和空文本均排除。本人发送仅作回复目标，对方发送仅作上下文。

按会话、时间和消息 ID 排序，以最近 8 条消息、30 分钟窗口查找缺失记录。若直接前一条缺失，或回答含“这个”“听语音”等依赖表达，或是短回答，则标为上下文不足；其他附近缺失也保留来源 ID 和质量标记。不同会话的缺失记录不串联，不生成附件正文。阈值是首版可调规则，T3 应在事件切分时继续复核。

排除原因允许重叠，不能把各原因计数相加当作排除总数。T3 生成完整问答时仍须确认所有上下文消息的复核状态、时间边界和引用关系，不能把候选目标与未复核上下文直接拼接。

首批按可读比例和本人可读发言数选择；话题涵盖学习、协调和日常交流。关系类型全部保留 `unknown`；不能从聊天口吻推断“朋友”“老师”等身份。场景标签附有实际消息依据，未知话题也保留未知。

## T3：事件与样本流水线（2026-10-04）

T3.1—T3.7 已实现并在 T2 首批 4 个私聊上运行。源库保持只读；全部含聊天正文的产物放在 `data/private/t3/`。初次运行的产物位于 `data/private/t3_initial/`，用于本次复核和修正对照，不是冻结基线。

### 方法

`normalize.py` 按会话、时间、原消息 ID 稳定排序，同秒保持来源顺序。用批次与消息主键识别重复导入：同键同记录跳过，同键不同记录报错；不同来源键的相同文本不去重。异常时间保留在隔离记录中，不推断一个日期。

`episodes.py` 将同一个说话人、同一收发方向、同一天且相隔不超过 60 秒的普通文本合并。对方插话、媒体/压缩消息、日期变化和引用起点都停止合并。回复组保留全部子消息 ID 与原文本行边界。

事件切分参考 30 分钟间隔、北京时间日期变化、缺失/结构化消息和话题变化。明确换话题表达可触发切分；长文本在至少 5 分钟间隔下的低字符重合仅作保守话题线索，不声称模型语义识别。精确且向后的引用可以保持跨时间、跨日期联系；其他异步短回应保留歧义，不仅因相邻就绑定为回答。

引用解析只在本地读取原始 JSONL 的关联元数据。原始服务端标识不进入输出，输出引用使用当前清洗批次的消息 ID。未解码的结构化消息记录为引用未知，不能认定其中一定存在引用，也不能从占位恢复正文。引用缺失、歧义或指向未来的内容不补成虚构问答。

每个目标取同事件内之前最多 6 个回复组及必要引用。目标只能是本人连续发言；对方只作上下文。目标及每条上下文均须在私有复核记录中通过；样本不包含目标之后的信息。孤立指代、纯表情且缺乏实质内容的起始上下文、无此前对方上下文和无法确认的异步回应均排除。候选关系标为 `adjacent_candidate`，不冒充微信明确回复关系。

### 划分与产物

以完整事件为单元，先将有明确引用的关联事件组成一个组，再按组的末尾时间排序，参考 80%/10%/10% 分配 train/dev/test。整个关联组归同一集合；不会拆开跨边界事件或把引用目标放进另一个集合。此比例用于事件组，少量且不均匀的可用样本不保证相同数量比例，本次样本比例为 84/6/20。

| 文件 | 用途 |
|---|---|
| `normalized_messages.jsonl` / `normalization.json` | 排序消息及重复、异常时间记录 |
| `turns.jsonl` / `episodes.jsonl` | 连续回复组与事件、切分原因、缺失消息 ID |
| `references.json` / `reply_links.jsonl` | 可解析引用、未知/歧义状态及候选配对与排除原因 |
| `review_proposals.jsonl` | 私有候选复核输入，不作为可用训练样本 |
| `dialogue_examples.jsonl` | 已通过来源及质量筛选的完整问答 |
| `train.jsonl` / `dev.jsonl` / `test.jsonl` | 按整事件分配的可用样本 |
| `training_style_examples.jsonl` | 仅训练集的后续风格检索输入，不混入 dev/test 目标 |
| `message_reviews.json` / `quality_review.json` | T3 新增来源复核与 50/100 项检查、真实修正证据 |
| `parameters.json` / `split_assignment.json` | 可调整参数和事件集合分配 |
| `statistics.json` / `verification.json` | 实测统计与来源、时序、集合隔离验证 |

实测验证保留全部 1,830 条消息在回复组和事件中的唯一位置，合并文本与子消息完全一致；全部目标只含本人发言，上下文在目标之前且来源已复核。train/dev/test 之间既无共享事件，也无共享消息。训练检索输入与 train 文件完全一致，尚未建立风格 FAISS 索引。

```powershell
.venv\Scripts\python.exe -m aitown.data_pipeline.pipeline --reviews data/private/t3/message_reviews.json --output data/private/t3
```

默认只读取首批会话清单；`--database`、`--selection`、`--reviews`、`--source` 和 `--output` 可指定输入输出。`--merge-seconds`、`--episode-seconds`、`--topic-seconds`、`--ambiguous-seconds` 与 `--context-turns` 可调整。使用 T2 旧复核文件运行仅得到 2 个完整样本，不能因数量少而放行未复核上下文；本次 110 个样本使用额外完成的 T3 来源复核。

当前不足包括未知称谓、普通词误遮盖、缺失压缩正文及依赖规则的语义切分。它们继续记录或排除，不用生成文本弥补。关系类型仍为未知，不能将对方的经历抽取为本人事实；事实与应用数据库属于 T4、T5。

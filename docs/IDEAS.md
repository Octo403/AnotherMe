# AI 小镇可以做的四个实验

这些是围绕本工作区课程要求提出的设计方案，尚未实现的能力不计入当前功能。

## 1. 为一个共同目标协作的小镇（建议先做）

目标：周末举办读书交流会。图书管理员知道场地条件，咖啡店主知道饮品价格，居民有自己的时间与偏好。公共资料、私人记忆、工具计算共同影响决策。

有趣之处：不是让所有角色无条件同意，而是让预算、时间、容量产生真实约束。先表达意向，再提出方案，用技能核算，最后形成可执行计划。

最小下一步：3 名居民、一个场地、一个公共任务；增加提议、承诺、执行三类行为和明确的世界状态更新。衡量最终方案是否满足容量与预算、是否重复承诺、是否虚构事实。这与课程的 RAG、上下文隔离、技能和结构化调度最容易结合。

## 2. 消息如何变成传闻的小镇

一个居民获知“图书馆周六关闭”，其他居民通过有限的邻里交流得知消息。消息可能过期，也可能仅是未经确认的猜测。观察谁会去查原始公告，谁会把传闻当事实。

最小下一步：为消息记录来源、发生时间和确认状态；居民有不同信任倾向。比较有无检索、自省时的错误传播比例与纠正速度。私人记忆与公共知识冲突在这里是研究对象。

## 3. 具有长期关系变化的小镇

居民会记住谁兑现了承诺、谁提供过帮助，并据此选择下次的合作对象。关系变化由具体事件产生，而不是每次随机生成性格描述。

最小下一步：保存少量情节记忆和关系数值，用发生过的事件解释数值变化。讨论的关键是“角色是否前后一致”，可评估承诺履行率与记忆冲突次数。需要世界事件存储与记忆总结，难度比第一项高。

## 4. 可干预、可观察的小镇实验室

用户注入一次公共事件，比如活动室临时关闭，观察居民如何发现影响、重新规划、协调安排。界面展示位置、当前目标、公开发言和行为依据。

最小下一步：先用时间轴与事件面板，不急于制作复杂地图。记录每个行动读取了哪些知识、使用了哪些工具，以及造成什么世界状态变化。衡量恢复到可行方案的轮次、模型调用次数和无效行动次数。

## 建议的推进顺序

1. 当前底座：两居民、共享资料、独立历史、技能与五节点图。
2. 验证在线角色对话与真实检索，收集成功及失败样例。
3. 选一个公共目标，加入有限行动与世界状态，把聊天变成实际协调。
4. 加入长期记忆和关系变化，再设计可视化。

讨论时最值得确定的三件事：居民要达成什么目标；哪些资源和利益会产生冲突；怎样判断它们确实完成了任务。
